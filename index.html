Production Notes

So... how did we get here?

Director's Cut started as a fun useless idea: what if completely normal human actions received the unnecessary cinematic treatment they clearly never asked for? Somewhere between setup errors, song hunting, dinner, Musical Night, AI tools and documentation confusion, it slowly became an actual project.

💡

The Idea

Detect everyday actions through a webcam and automatically turn them into dramatic movie moments.

💻

The Engineering

Computer vision, a web interface, action detection, automatic music, captions and cinematic visual effects.

🫠

The Reality

Installation issues, too many song choices, documentation plot twists and approximately zero respect for the concept of sleeping early.

Scene 02 — The MacBook Incident

Abhirami had already installed the required setup on her MacBook before coming to the event.

Naturally, once we actually needed it... it decided not to work properly.

We spent almost half an hour trying to figure out what was wrong before finally creating a separate folder and reinstalling the required things again.

Eventually, the system cooperated and development could continue.

First 30 minutes of development: mostly developing patience.
MacBook installation arc 30 minutes gone
The original plan

Scene 03 — “Let's Just Code It Manually”

Our first plan was pretty straightforward.

We would manually create the project files, write the code ourselves and use GitHub Copilot as assistance while coding.

Very responsible. Very organised. Very temporary.

We started with that approach, but the project slowly began demanding more things than just code.

VS Code GitHub Copilot manual coding
Shortly after

Scene 04 — The Music Problem

Director's Cut was never going to work with boring default sounds.

Different actions needed different cinematic moods, which meant we had to actually sit down and decide which songs or background tracks would fit each scene.

Somehow, choosing music for someone drinking water became a legitimate development task.

Software engineering, but half the meeting is “wait... this song would be funnier.”
BGM song selection important research obviously
Meanwhile

Scene 05 — Meme Department Opens

Music alone was not enough.

Director's Cut also needed captions, reaction images and memes that could appear when actions were detected.

So naturally, part of our hackathon became two people seriously discussing which meme best represents someone performing an extremely normal action.

Scene 08 — The Antigravity Arc

When we returned, it became clear that manually managing every part of the project while also working on the content, music and documentation was becoming difficult.

So we changed strategy.

We decided to move development to Google Antigravity so we could manage the application more efficiently.

Ashwita already had Antigravity set up. Abhirami did not.

Which meant another installation side quest. Around 15 more minutes disappeared into setup.

New strategy unlocked: work smarter because the clock is starting to look suspicious.
Antigravity strategy change +15 min setup

Development continued, but the extremely serious question of which songs, reactions and captions belonged to each action was still alive.

audio memes again UI computer vision
Documentation side quest

Scene 10 — The Loading Page Lore

Then came one of the most confusing parts of the entire hackathon: figuring out what exactly a “loading page” meant.

At first, we were told to document the progress in an Excel sheet.

Okay. Spreadsheet. Fine.

Then the plan apparently changed to Microsoft Word.

Also fine.

And then we finally learned that the actual requirement was to create a completely separate Git branch named docs, create an index.html inside it, and turn that into a creative documentation page.

Excel → Word → Git branch → HTML.

Character development.
Excel? Word? docs branch ✓ index.html ✓
Around 2:30 AM

Scene 11 — Still Loading...

At around 2:30 in the morning, the project was still not completely finished.

There were still things to integrate, things to test, and probably at least one thing that would decide not to work the moment someone came to see the demo.

But honestly, that's basically every hackathon.

Somehow everything always comes together at the last possible minute.

Current strategy: keep going until it either works or becomes morning.

Scene 12 — Putting the Movie Together

Piece by piece, Director's Cut started behaving like an actual application instead of a collection of ideas scattered across laptops.

Was the problem useful? Absolutely not.

Was building it fun? Very much yes.

What We Learned

Somehow, actual lessons happened too

🧩

Plans Will Change

We began with one development workflow and eventually changed tools when the original plan stopped being practical.

⏱️

Small Things Take Time

Setup, installations, choosing assets and fixing tiny issues can quietly consume a surprising amount of hackathon time.

🎬

Useless Can Still Be Technical

The problem might be ridiculous, but building a system that reacts to real webcam input still requires actual engineering.

Final Scene

The movie was still in production.

Which, honestly, feels very on-brand for a hackathon.
